LapakDA — Master Technical Documentation (V6)

Versi Dokumen: 6.0.0 (Deep Technical Reference) | Tech Stack: Laravel 11/13, Blade, Alpine.js, Tailwind CSS, MySQL, ApexCharts, Leaflet, Web Push.

⚠️ ATURAN EMAS (GOLDEN RULES) UNTUK PROGRAMMER SELANJUTNYA:
1. JANGAN PERNAH MENEBAK ISI FILE. Selalu minta kode asli sebelum mengubah Controller/Model/View.
2. METODE CARI & GANTI: Gunakan instruksi "Cari baris X, ganti dengan Y". Jangan menimpa seluruh file jika hanya mengubah 1 baris.
3. ANALISIS AFTER-EFFECT: Setiap kali menambah kolom database/fitur, WAJIB cek View mana saja yang perlu diupdate.
4. JANGAN UBAH ALUR BACKEND: Logika PHP (OrderController, StoreController) sudah solid. Fokus perubahan di layer View/UI.
5. DESAIN: Tailwind CSS, warna brand #B9232D, font Plus Jakarta Sans. DILARANG pakai alert().
6. TIMEZONE: Server UTC, logika bisnis (isOpenNow) WAJIB konversi ke WIB (now('Asia/Jakarta')).
7. DOMAIN SEPARATION: Admin (SaaS) pisah dengan Seller (Operasional).
8. SERVER PRODUCTION: Nginx & PHP di-set maksimal upload 10MB, Laravel memvalidasi maksimal 5MB.

Struktur Folder & Referensi Kode

app/Http/Controllers/

OrderController.php

Ringkasan: Menangani checkout, pembuatan Order, dan integrasi WA.

FungsiDeskripsi
checkout(Request $request, Store $store)Menampilkan form checkout. Cek isOpenNow(). Jika toko tutup, redirect ke cart dengan error. Generate idempotencyKey.
store(Request $request, Store $store)Memproses pesanan. Memisahkan qty Dine-in/Takeaway. Menembakkan NewOrderNotification (Push Notif) ke HP Seller. Menyusun teks WA & redirect ke wa.me.
riwayat(Request $request)Menampilkan tab pesanan (Pesanan Saya & Masuk). Query berdasarkan user_id atau session_id.
susunRingkasanWA(Order $order, Store $store)Private. Merangkai teks pesanan (format Markdown WA) berisi item, total, tipe, no meja, & link Gmaps.
💡 Konteks/Alasan Desain: Idempotency digunakan (via Cache) untuk mencegah user klik tombol submit dua kali karena koneksi lambat yang bisa membuat 2 Order. Push Notification dipanggil tepat setelah order dibuat agar Seller langsung waspada.

StoreController.php

Ringkasan: Mengelola pendaftaran dan pengaturan toko (Resto/Toko).

FungsiDeskripsi
create()Menampilkan form pendaftaran. Cek apakah ini toko pertama (bebas biaya) atau ke-2+ (kena open fee). Mengambil data voucher.
store(Request $request)Memproses pendaftaran. Validasi voucher, hitung biaya buka, upload foto profil/background, simpan tagihan pending ke tabel subscriptions jika ada biaya.
update(Request $request, Store $store)Memproses update data toko. Mengompres gambar baru ke WebP.
💡 Konteks/Alasan Desain: Logika biaya buka (open_fee) dan voucher ditanam di Controller ini. Jika voucher valid, masa aktif diset 3 bulan (trial). Jika tidak, 1 bulan (active). Jika ini toko ke-2+, sistem otomatis membuat tagihan pending di tabel subscriptions tanpa menahan pembuatan toko.

ProductDashboardController.php

Ringkasan: CRUD produk seller.

FungsiDeskripsi
store() / update()Menyimpan produk. Mengecek input stok. Jika stok 0, status_tersedia dipaksa false.
prosesDanSimpanFoto($file)Private. Menggunakan Intervention Image v3 untuk scaleDown (800x800), pad, dan convert ke WebP (kualitas 80).

OrderDashboardController.php

Ringkasan: Manajemen pesanan masuk untuk Seller.

FungsiDeskripsi
index(Request $request, Store $store)Menampilkan pesanan. Dilengkapi filter status (Menunggu, Diproses, Selesai, Batal) dan hitungan per status.
allOrders()Menampilkan semua pesanan lintas toko milik Seller (digunakan di Tab Pesanan).
