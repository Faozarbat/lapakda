⚠️ ATURAN EMAS (GOLDEN RULES) UNTUK PROGRAMMER SELANJUTNYA:
Dokumen ini adalah hasil evolusi panjang. Jika Anda melanjutkan proyek ini, Anda WAJIB mematuhi aturan berikut:
1. JANGAN PERNAH MENEBAK ISI FILE. Selalu minta kode asli sebelum mengubah Controller/Model/View.

3. ANALISIS AFTER-EFFECT: Setiap kali menambah kolom database, WAJIB cek View mana saja yang perlu diupdate (contoh: menambah foto profil, wajib update halaman Jelajah & Katalog).

5. DESAIN: Gunakan Tailwind CSS, warna brand #B9232D, font Plus Jakarta Sans. DILARANG menggunakan alert() bawaan browser (gunakan Toast Alpine.js).
6. TIMEZONE: Server menggunakan UTC, tapi logika bisnis (terutama jam operasional) WAJIB dikonversi ke WIB (now('Asia/Jakarta')).
7. DOMAIN SEPARATION: Jangan mencampur logika Panel Admin (SaaS) dengan Dashboard Seller (Operasional Toko). Admin mengurus langganan, Seller mengurus jualan.

1. Gambaran Umum Arsitektur

LapakDA adalah platform katalog online multi-tenant (SaaS) untuk UMKM. Sistem ini memiliki 3 aktor utama: Pembeli (Customer), Penjual (Seller/Owner), dan Admin.

  • Customer: Menjelajah katalog, mencari produk, checkout (via WA), dan melihat riwayat pesanan. Mendukung guest checkout.
  • Seller: Mengelola toko, produk, stok, pesanan, dan melanggan sistem (SaaS).
  • Admin: Memverifikasi pembayaran seller, mengelola voucher, mengatur harga langganan, dan memantau sistem via Dashboard Premium.

4. Alur Logika Bisnis (Business Logic)

💡 Alur Pendaftaran Toko & Langganan:
1. User klik "Daftar Toko". Cek: Toko pertama? Biaya buka Rp 0. Toko ke-2+? Biaya buka Rp 20.000.
2. Validasi Voucher (misal: UNDANGAN). Jika valid, active_until 3 bulan (trial).
3. Tanpa voucher: active_until 1 bulan (active).
4. Jika ada biaya buka, buat tagihan di subscriptions (pending).
💡 Perbedaan Resto vs Toko (Domain Separation):
- Resto: Checkout punya fitur Dine-in (Makan di tempat) & Input Nomor Meja.
- Toko: Fitur Dine-in disembunyikan. Checkout otomatis Takeaway/Delivery. Label di katalog diganti dari "Menu" menjadi "Produk".
💡 Logika Stok Produk:
Kolom stok bersifat opsional. Jika diisi angka (misal 10), katalog menampilkan "Sisa 10". Jika diisi 0, sistem otomatis mematikan status_tersedia (pembeli tidak bisa tambah ke keranjang).

5. Security Checklist & Deployment

Audit Keamanan: Proyek ini sudah dilindungi dari IDOR (Authorization), Mass Assignment ($fillable), SQL Injection (Eloquent Binding), dan XSS (Blade Escaping). File Upload divalidasi ketat (hanya gambar, max 5MB) dan disimpan di folder storage.
Wajib dijalankan sebelum Go-Live (Production):
  • APP_ENV=production dan APP_DEBUG=false di file .env.
  • Pastikan APP_KEY sudah di-generate dan unik.
  • Aktifkan HTTPS (SSL) di hosting.
  • Jalankan npm run build (bukan dev) untuk optimasi CSS/JS.
  • Jalankan php artisan optimize dan php artisan config:cache.
  • Setup Cronjob di cPanel/VPS: * * * * * php /path-to-project/artisan schedule:run >> /dev/null 2>&1.
