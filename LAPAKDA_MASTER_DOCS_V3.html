LapakDA — Ultimate Technical Documentation (V5)

Versi Dokumen: 5.0.0 (Handover & Blueprint) | Tech Stack: Laravel 11/13, Blade, Alpine.js, Tailwind CSS, MySQL, ApexCharts, Leaflet, Web Push API.

⚠️ ATURAN EMAS (GOLDEN RULES) UNTUK PROGRAMMER SELANJUTNYA:
1. JANGAN PERNAH MENEBAK ISI FILE. Selalu minta kode asli sebelum mengubah Controller/Model/View.
2. METODE CARI & GANTI: Gunakan instruksi "Cari baris X, ganti dengan Y". Jangan menimpa seluruh file jika hanya mengubah 1 baris (kecuali diminta versi full).
3. ANALISIS AFTER-EFFECT: Setiap kali menambah kolom database/fitur, WAJIB cek View mana saja yang perlu diupdate (misal: nambah stok, wajib update create, edit, dan katalog).
4. JANGAN UBAH ALUR BACKEND: Logika PHP (OrderController, StoreController) sudah solid. Fokus perubahan di layer View/UI.
5. DESAIN: Tailwind CSS, warna brand #B9232D, font Plus Jakarta Sans. DILARANG pakai alert() (pakai Toast Alpine.js atau div error).
6. TIMEZONE: Server UTC, logika bisnis (isOpenNow) WAJIB konversi ke WIB (now('Asia/Jakarta')).
7. DOMAIN SEPARATION: Admin (SaaS) pisah dengan Seller (Operasional).
8. SERVER PRODUCTION: Nginx & PHP di-set maksimal upload 10MB, Laravel memvalidasi maksimal 5MB (WebP Compression).

1. Gambaran Umum Arsitektur

LapakDA adalah platform katalog online multi-tenant (SaaS) untuk UMKM. Sistem ini memiliki 3 aktor utama: Pembeli (Customer), Penjual (Seller/Owner), dan Admin.

app/Http/Controllers/

StoreController.php

Ringkasan: Mengelola pendaftaran dan pengaturan toko (Resto/Toko).

FungsiDeskripsi
create()Menampilkan form pendaftaran. Cek apakah ini toko pertama (bebas biaya) atau ke-2+ (kena open fee). Mengambil data voucher.
store(Request $request)Memproses pendaftaran. Validasi voucher, hitung biaya buka, upload foto profil/background, simpan tagihan pending ke tabel subscriptions jika ada biaya.
edit(Store $store)Menampilkan form edit toko (Jam operasional, Lokasi, Foto, Status).
update(Request $request, Store $store)Memproses update data toko. Mengompres gambar baru ke WebP.
preview(Store $store)Menampilkan pratinjau toko (Mode Read-Only untuk Seller).
💡 Konteks/Alasan Desain: Logika biaya buka (open_fee) dan voucher ditanam di Controller ini. Jika voucher valid, masa aktif diset 3 bulan (trial). Jika tidak, 1 bulan (active). Jika ini toko ke-2+, sistem otomatis membuat tagihan pending di tabel subscriptions tanpa menahan pembuatan toko, agar seller bisa langsung isi produk sambil menunggu verifikasi admin.
OrderController.php

Ringkasan: Menangani checkout, pembuatan Order, dan integrasi WA.

FungsiDeskripsi
checkout(Request $request, Store $store)Menampilkan form checkout. Cek isOpenNow(). Jika toko tutup, redirect ke cart dengan error. Generate idempotencyKey.
store(Request $request, Store $store)Memproses pesanan. Memisahkan qty Dine-in/Takeaway. Menembakkan NewOrderNotification (Push Notif) ke HP Seller. Menyusun teks WA & redirect ke wa.me.
riwayat(Request $request)Menampilkan riwayat pesanan pembeli (berdasarkan user_id atau session_id).
susunRingkasanWA(Order $order, Store $store)Private. Merangkai teks pesanan (format Markdown WA) berisi item, total, tipe, no meja, & link Gmaps.
💡 Konteks/Alasan Desain: Idempotency digunakan (via Cache) untuk mencegah user klik tombol submit dua kali karena koneksi lambat yang bisa membuat 2 Order. Push Notification dipanggil tepat setelah order dibuat agar Seller langsung waspada.

3. Alur Logika Bisnis & Keamanan

Alur Langganan (SaaS):
1. Toko pertama = Gratis biaya buka. Toko ke-2+ = Bayar Rp 20.000 (masuk tabel subscriptions pending).
2. Voucher (UNDANGAN) = Bebas biaya langganan 3 bulan (trial).
3. Tanpa voucher = active_until diset 1 bulan.
4. Cronjob subscriptions:check-expiry jalan tiap malam. Jika telat bayar lewat 3 hari (grace period), status jadi archived & hilang dari publik.
Keamanan Upload (Anti 413 Error):
Nginx diset client_max_body_size 10M. Laravel validasi max:5120 (5MB). Javascript di frontend menolak file > 5MB sebelum dikirim ke server. Server lalu mengompres gambar jadi WebP (50-100KB).
