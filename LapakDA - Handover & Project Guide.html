Gambaran Umum Arsitektur

LapakDA adalah platform katalog online multi-tenant untuk UMKM (fokus awal: Resto). Menggunakan pola MVC Laravel. Logika bisnis diletakkan di Controller dan Model, sementara antarmuka menggunakan Blade dengan Tailwind CSS dan Alpine.js untuk interaktivitas ringan. Data keranjang dan pesanan terikat pada session_id (untuk guest) atau user_id (untuk login).

Database Schema (MySQL)

Skema ini adalah hasil akhir dari seluruh migrasi yang sudah dijalankan.

orders & order_items orders: store_id, user_id (nullable), session_id, nomor_order, fulfillment_type (self_pickup/delivery), status (menunggu_konfirmasi, dikonfirmasi, selesai, dibatalkan), delivery_latitude, delivery_longitude, delivery_note. order_items: order_id, product_id (nullable), nama_produk_saat_beli, harga_saat_beli, qty, consumption_type (dine_in/takeaway), table_number.
reviews id, order_id (FK), store_id (FK), user_id (FK), rating (1-5), comment.
💡 Konteks/Alasan Desain Database:
1. Snapshot Harga: Di order_items, nama dan harga produk disimpan sebagai string/integer (nama_produk_saat_beli, harga_saat_beli). Ini sengaja dilakukan agar jika pemilik toko mengubah harga di kemudian hari, riwayat pesanan lama tidak ikut berubah.
2. Session ID vs User ID: Sistem mendukung guest checkout. Pesanan guest diikat ke session_id. Jika guest mendaftar akun, data pesanan dengan session_id tersebut dipindahkan ke user_id yang baru.
3. SoftDeletes pada Order: Tabel orders tidak boleh dihapus permanen karena dibutuhkan untuk rekonsiliasi dan history.
app/Http/Controllers/

OrderController.php

Ringkasan: Controller paling kompleks. Menangani form checkout, kalkulasi total, pemisahan qty (dine-in/takeaway), pencegahan double-order (idempotency), dan generate link WhatsApp.

FungsiDeskripsi
checkout(Request $request, Store $store)Menampilkan form checkout. Membuat token unik $idempotencyKey (UUID) baru setiap kali halaman dibuka untuk mencegah double-submit. Memvalidasi apakah produk di keranjang masih tersedia.
store(Request $request, Store $store)Memproses pesanan. Memvalidasi ulang token idempotency (jika token sudah ada di Cache, redirect ke URL WA yang sama). Membuat record Order dan OrderItem (memisahkan baris jika ada split qty Dine-in/Takeaway). Menyusun teks WA dan redirect ke wa.me.
riwayat(Request $request)Menampilkan riwayat pesanan. Jika login, query berdasarkan user_id. Jika guest, berdasarkan session_id.
cekProdukMasihTersedia(Cart $cart, Store $store)Private method. Memastikan semua produk di keranjang statusnya masih tersedia sebelum checkout disimpan.
susunRingkasanWA(Order $order, Store $store)Private method. Merangkai teks pesanan (format Markdown WA) yang berisi daftar item, total, tipe fulfillment, nomor meja, dan link Google Maps (jika delivery).
💡 Konteks/Alasan Desain:
Idempotency: Menggunakan Cache::get('checkout_idempotency:...') selama 1 jam. Ini mencegah user tidak sengaja mengklik tombol submit dua kali (karena koneksi lambat) yang bisa membuat 2 record Order. Jika user membuka ulang halaman checkout, dia mendapat token baru (order baru yang sah).

ProductDashboardController.php

Ringkasan: Mengelola CRUD produk untuk pemilik toko. Termasuk pemrosesan foto produk.

FungsiDeskripsi
index(Store $store)Menampilkan grid produk milik toko.
store(Request $request, Store $store)Menyimpan produk baru. Memanggil prosesDanSimpanFoto jika ada upload.
update(Request $request, Store $store, Product $product)Memperbarui produk. Menghapus foto lama dari storage jika user mengunggah foto baru.
prosesDanSimpanFoto($file)Private method. Menggunakan Intervention Image untuk scaleDown (resize maks 800x800) dan pad (menambah background putih agar persegi sempurna), lalu dikonversi ke format WebP kualitas 80. Nama file menggunakan UUID.
💡 Konteks/Alasan Desain (Foto):
Menggunakan scaleDown + pad (bukan cover) agar foto asli tidak terpotong (cropped). WebP dipilih agar ukuran file di server sangat kecil, menghemat bandwidth saat katalog diakses lewat HP pembeli.

CartController.php & GuestAuthController.php

Cart: Menangani add (via AJAX/Fetch), index (multi-toko), updateQty, dan remove. Keamanan menggunakan pencocokan session_id.

GuestAuth: Menangani form popup "Isi Nama & No HP". Melakukan Silent Register (membuat User baru dengan password acak) dan memindahkan semua Order guest (session_id lama) ke user_id yang baru terbentuk agar riwayat tidak hilang.

Lampiran A: Pelajaran Penting & Known Issues (Dari Sesi Sebelumnya)

Instruksi Wajib: AI baru harus membaca riwayat kesalahan di bawah ini agar tidak mengulanginya.
  • PR-1 (Fatal): MENEBAK ISI FILE. AI sebelumnya sering berasumsi sebuah controller/view isinya A, padahal B. Ini menyebabkan error berantai. Solusi: SELALU minta isi file asli sebelum diedit.
  • PR-2 (Fatal): Mengubah Alur Backend. Saat merombak UI, AI sebelumnya malah mengubah logika pemrosesan order dan membuatnya error. Solusi: UI hanya boleh diubah di layer View (Blade). Logika bisnis (PHP) tidak boleh diutak-atik tanpa izin.
  • PR-3: Infinite Back-Loop. Tombol Back di halaman Keranjang dan Checkout menggunakan url()->previous(), menyebabkan user terjebak bolak-balik. Solusi: Kunci route back button (misal Keranjang selalu back ke Katalog, Checkout selalu back ke Keranjang).
  • PR-4: Live Preview Disaster. Tombol "Pratinjau" di Dashboard Owner awalnya mengarah ke URL publik asli, sehingga Owner bisa membuat pesanan palsu ke tokonya sendiri. Solusi: Buat rute khusus /dashboard/preview/{store} dan kirim flag $isPreview untuk mematikan tombol keranjang.
  • PR-5: Windows Symlink. Jika gambar produk tidak muncul, jalankan php artisan storage:link. Jika Windows memblokir penghapusan folder symlink lama, gunakan CMD Administrator: rmdir /s /q "path\to\public\storage".

Lampiran C: Master Plan Monetisasi (Subscription Model)

Konteks Bisnis (Wajib Diimplementasikan):
LapakDA menggunakan model bisnis Langganan (SaaS), bukan potongan per transaksi. Sistem harus mendukung fitur ini agar platform bisa menghasilkan pendapatan.

Skema Harga & Masa Aktif

  • Bulan 1–3: Gratis (Free Trial).
  • Bulan 4–6: Diskon 50% (Rp 5.000 / bulan).
  • Bulan 7+: Harga Normal (Rp 10.000 / bulan).
  • Catatan: Harga normal bisa diubah secara dinamis oleh Admin melalui Panel Admin.

Konsekuensi (Auto-Archive)

  • Jika toko melewati tanggal jatuh tempo (belum membayar), status toko otomatis menjadi Arsip / Non-Aktif.
  • Toko yang diarsipkan tidak akan muncul di Beranda (Home), halaman Jelajah (Jelajah), maupun URL Publik katalognya (menampilkan halaman toko nonaktif).
  • Pemilik toko tetap bisa login ke Dashboard untuk memperpanjang masa aktif.

Lampiran D: Catatan Teknis Kritis & Setup Lingkungan (WAJIB BACA)

Instruksi Setup untuk AI Baru:
  • Vite / Tailwind Build: Setiap kali mengubah class Tailwind di file Blade, AI WAJIB mengingatkan user untuk menjalankan npm run dev (atau npm run build). Jika tidak, perubahan desain tidak akan muncul (ini kesalahan klasik di versi lama).
  • Seeder Database: Jangan jalankan DemoDataSeeder sebelum KecamatanSeeder. Jika urutannya terbalik, akan error karena data kecamatan kosong.
  • Symlink Storage: Jika gambar tidak muncul, jalankan php artisan storage:link. Jika Windows gagal karena file exists, hapus manual folder public/storage via CMD Administrator (rmdir /s /q public\storage) lalu jalankan ulang.

Penjelasan Teknis yang Sering Bikin Salah Paham

  • Alpine.js v3: Proyek ini menggunakan Alpine v3 (bawaan Breeze terbaru). JANGAN gunakan trik lama seperti document.querySelector('body').__x.$data untuk manipulasi state. Gunakan window.dispatchEvent(new CustomEvent('nama-event', { detail: {...} })) atau x-model secara langsung.
  • Bypass OTP: Di dalam file web.php masih terdapat rute /verifikasi-otp dan OtpController. ABAIKAN INI. Alur login/register saat ini sengaja menggunakan sistem Silent Register (isi nama + no HP langsung masuk) demi mengejar database user. Jangan mengaktifkan OTP kecuali diminta secara eksplisit.
  • Login Ganda (Admin vs User): User biasa login hanya dengan Nomor HP (tanpa password). Admin login dengan Nomor HP + Password. Logika ini ada di LoginRequest.php. Jangan diubah.
  • Intervention Image v3: Pemrosesan foto produk di ProductDashboardController menggunakan sintaks v3 (read(), scaleDown(), pad(), toWebp(80)). Jangan gunakan sintaks v2 (make()).
  • Preview Mode: Di halaman katalog store/show.blade.php, variabel $isPreview digunakan untuk mematikan tombol keranjang jika diakses oleh Owner. Pastikan logika ini tidak terhapus.
  • File .env: Jangan pernah mengubah APP_URL di .env tanpa izin, karena ini memengaruhi link gambar dan redirect wa.me.
